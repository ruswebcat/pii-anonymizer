# Прокси обезличивания персональных данных (LLM-guard)

**Что это.** HTTP-прокси между ИИ-агентом и внешними языковыми моделями. Заменяет данные клиентов
на обезличенные коды (идентификаторы) до отправки в модель и восстанавливает значения **внутри
контура оператора** — на каналах, перечисленных в настройке `detok_channels` (умолчание публичной
сборки — любой канал), и в локальных файлах. Канал вне контура значения не получает никогда.
Оператору, которому приватность важнее удобства, список каналов следует сузить — почему и как,
сказано в `docs/PRIVACY.md`.

**Зачем.** Агент решает операционные задачи по клиентской базе (списки обзвона, разборы анкет,
отчёты по клубам) через внешнего поставщика модели. Передача персональных данных клиентов внешнему
получателю недопустима, а отказ от ИИ-помощника не нужен: обезличивание сохраняет
работоспособность процессов, не передавая наружу данные о личности.

**Для кого.** Для любого оператора, который обрабатывает персональные данные клиентов и хочет
пользоваться внешней языковой моделью: сеть фитнес-клубов, клиника, салон, сервисная компания.
Ничего специфического для конкретной организации в коде нет — название организации, филиалы,
тарифы, город, телефоны ресепции, свои адреса и названия доверенных каналов задаются
конфигурацией: `config.example.yaml` и `deploy/pii-proxy.env.example`.

**Где стоит.** На том же хосте контура, что и агент. Слушает только локальный интерфейс (loopback,
порт по умолчанию **8791**) и недоступен из сети. Ключи поставщиков моделей живут в прокси, а
агент держит заглушку: это единственная точка выхода LLM-трафика. Состояние (справочник
соответствия, словарь, слой имён, ключи) — файлы вне репозитория, см. `docs/OPERATIONS.md`.

**Юридическая рамка:** 152-ФЗ и метод № 1 «введение идентификаторов» Требований к обезличиванию
(приказ Роскомнадзора от 19.06.2025 № 140) — разбор своими словами в `docs/PRIVACY.md`.
Действующие документы оператора: регламент обезличивания `docs/REGULATION.md`, акт теста на
обратимую идентификацию `docs/ACT.md`, техническое задание `docs/SPECIFICATION.md`.

## Что делает

| Класс | Что заменяется |
|---|---|
| ФИО | имена клиентов в любой записи, включая латиницу |
| Телефон | мобильные и городские в семи формах записи (`+7 …`, `8 (…) …`, слитно, через дефис) |
| Почта | адреса электронной почты |
| Дата рождения | день и месяц; **год остаётся открытым** по решению оператора |
| Адрес | адреса клиентов |
| Номер карты клиента | номера карт и клиентские идентификаторы |
| Документы | СНИЛС, паспорт, ИНН |

- **Обезличивается весь запрос, а не только сообщение пользователя:** системный текст, история
  диалога, результаты инструментов и аргументы `tool_calls`.
- **Коды детерминированные:** одинаковое значение всегда даёт одинаковый код, поэтому кэш
  поставщика модели не ломается.
- **Fail-closed и деградация вместо отказа.** Если заслон нашёл остаток ПД, запрос дотокенизируется
  вторым проходом и доходит до пользователя, а факт пишется в журнал инцидентов; если починка не
  удалась (сбой справочника, исчерпание кодов) — запрос в модель не уходит (`403`).
- **Восстановление по каналам:** аргументы инструментов — всегда; текст ответа — по настройке
  `PII_PROXY_DETOK_CHANNELS` (список каналов либо `*` — «любой канал», умолчание публичной сборки).
  Канал вне контура не детокенизируется ни при каком значении настройки, и указать его в списке
  нельзя: служба отказывается стартовать.
- **Только stdlib Python 3.11** плюс уже установленные `cryptography` и `pymorphy3`.

## Как проверить, что служба работает

```bash
curl -s http://localhost:8791/healthz | python3 -m json.tool
systemctl --user status pii-proxy.service    # или systemctl, если юнит системный
```

`healthz` отдаёт состояния слоёв: `store`, `cache`, `dictionary`, `name_layer`, `ner`, `rarity`,
`validator`, `incident_journal`, `registry`, `coherence`, `provider_cache`, а также число слов
собственной лексики организации, принятой из настроек. Если слой не поднялся или лексика пуста,
это видно здесь, а не подразумевается. Подробности — `docs/OPERATIONS.md`.

## Как начать пользоваться: адрес модели — это адрес прокси

Запустить службу мало. Пока в клиенте указан адрес поставщика напрямую, трафик идёт **мимо** прокси:
ни обезличивания, ни восстановления в таких запросах нет. **В клиенте нужно указать адрес прокси
как адрес модели** (для OpenAI-совместимого клиента это `base_url`), а ключ поставщика заменить
заглушкой — настоящий ключ живёт только в файле окружения прокси.

Адрес: `http://127.0.0.1:8791/<маршрут>/…`, где `<маршрут>` — имя из раздела `routes` настроек
(`ds`, `nord`); порт по умолчанию — 8791.

| Клиент | Что задать | Значение |
|---|---|---|
| Claude Code (CLI) | `ANTHROPIC_BASE_URL`, ключ-заглушка — `ANTHROPIC_AUTH_TOKEN` | `http://127.0.0.1:8791/<маршрут>` |
| OpenAI Codex CLI | `base_url` провайдера в `~/.codex/config.toml` | `http://127.0.0.1:8791/<маршрут>/v1` |
| VS Code и его форки | `base_url` того расширения, которое зовёт модель (`Continue`, `Cline` и подобные) | адрес прокси |
| Cursor IDE | «Override OpenAI Base URL» | **локальный адрес не заработает**: запросы Cursor уходят с его серверов и до loopback не доходят |

Готовые настройки клиентов, оговорки и обходные пути для Cursor — `docs/OPERATIONS.md`, раздел 5.1.
Там же сказано прямо, чего прокси не делает: он не переводит протоколы, поэтому маршрут обязан вести
к поставщику, говорящему на том же языке, что клиент (Claude Code — Anthropic Messages API,
Codex CLI — Responses API, остальные — Chat Completions).

## Кто отвечает за контур

- **Оператор (владелец данных и решений):** организация, эксплуатирующая контур. Оператор
  утверждает режимы работы, переключение агента на прокси и правки справочника и заполняет
  `config.example.yaml` своими значениями.
- **Эксплуатация:** администратор хоста контура, на котором живут агент и прокси
  (`docs/OPERATIONS.md`).
- **Документы для регулятора:** `docs/PRIVACY.md`, регламент и акт.

## Своя лексика организации — в настройках, а не в коде

Бренд, названия филиалов и тарифов, город, свои адреса и телефоны ресепции законно попадают в
словарь клиентов: часть карточек заведена с адресом или телефоном клуба. Чтобы они не заменялись
как данные клиента, оператор перечисляет их в настройках. Код при этом не знает ничьей лексики и
работает «из коробки» сразу после заполнения примера:

```yaml
# config.example.yaml
own_vocabulary:
  terms: ["<название организации>", "<филиал>", "<тариф>", "<город>"]
  addresses: ["<адрес клуба>"]
  phones: ["<телефон ресепции>"]
  service_objects: ["<название вашей системы учёта>"]
```

Те же значения задаются переменными окружения (`PII_PROXY_OWN_TERMS`,
`PII_PROXY_OWN_ADDRESSES`, `PII_PROXY_OWN_PHONES`, `PII_PROXY_OWN_SERVICE_OBJECTS`) или файлом
`PII_PROXY_OWN_VOCAB`. Пустое значение — безопасное умолчание публичной сборки: нечего
отбрасывать сверх общей части.

## Служебная лексика — тоже в настройках

Рядом с `own_vocabulary` есть отдельный раздел `service_lexicon`: тарифы, названия клубов и услуг,
которые система учёта оставляет в поле ФИО карточки. У этих списков разные работы, поэтому и ключи
разные: `own_vocabulary` — **стоп-лист распознавания** («эти слова наши, их никогда не заменять»),
а `service_lexicon` — **список замера** для измерителя шума справочника
(`tools/dict_noise_report.py`): сколько таких слов лежит в словаре как «имена». Смешивать их нельзя —
иначе добавление слова в список замера молча меняло бы поведение детектора.

```yaml
# config.example.yaml
service_lexicon:
  "тарифы и клубы": ["<тариф>", "<название клуба>"]
  "услуги и группы": ["<групповое занятие>", "<услуга>"]
```

Те же значения — строкой окружения `PII_PROXY_SERVICE_LEXICON` или файлом
`PII_PROXY_SERVICE_LEXICON_FILE` (JSON с категориями). В коде публичной сборки клубно-тарифных слов
нет: у другой сети тарифы называются иначе, а публиковать лексику одной сети сборка не должна.
Общие категории (должности, статусы, поля системы учёта, шаблоны-заглушки, обрывки) остались в
коде — они встречаются в карточке любой организации. Умолчание раздела — пусто: измеритель честно
работает по общим категориям, а своя лексика из `own_vocabulary` замеряется наравне с ними.

## Доверенные клиенты: кому отдаются восстановленные значения

Восстанавливать значения разрешено не всем: получателя выбирает оператор. Hermes называет канал
меткой в системном промпте, а сторонние ИИ-приложения (Cursor, Claude Code, Codex и другие) таких
меток не шлют — поэтому с 26.09.2026 клиент опознаётся сам, по трём источникам по порядку:

| Источник | Как задаётся | Надёжность |
|---|---|---|
| Заголовок | клиент ставит `X-PII-Channel: cursor` | называет канал, но подделывается |
| Ключ доступа | клиент ставит `X-PII-Client-Key`, в настройке — его **отпечаток** (`key_sha256`) | единственный, который нельзя предъявить, не зная ключа |
| User-Agent | шаблон (glob) в настройке, например `*cursor*` | называет канал, но подделывается |

Шаблоны пишутся **без номера версии** (`*cursor*`, `*claude-cli*`, `*codex*`): строку клиента
меняет каждое обновление, и шаблон с версией перестаёт совпадать молча. Фактическую строку снимают
на своей стороне (`python3 tools/ua_probe.py`), опознание проверяют прибором
(`python3 -m src.client_identity check …`) — оба шага, вместе с честной пометкой о том, какие строки
подтверждены, а какие нет, описаны в `docs/OPERATIONS.md`, раздел 5.1.

Клиент, который не назвался **ничем**, значений не получает: умолчание публичной сборки —
`unknown_client: keep_codes` (безопасное). Значение `restore` возвращает прежнее поведение и
ставится осознанно.

```yaml
# config.example.yaml
unknown_client: "keep_codes"
# trusted_clients:
#   - channel: cursor
#     user_agent: ["*cursor*"]           # способ 3: заголовки Cursor не настраивает
#   - channel: claude-code
#     key_sha256: "sha256:<отпечаток>"   # способ 2: python3 -m src.client_identity "$(cat ключ)"
#     user_agent: ["*claude-cli*"]       # способ 3 — запасной
#   - channel: codex
#     user_agent: ["*codex*"]
#   - channel: office
#     header_value: office               # способ 1: клиент ставит X-PII-Channel: office
```

Заголовок и User-Agent — **не граница безопасности**: их подделывает любой, кто может поставить
запрос на прокси. Граница — ключ на клиента и то, что служба слушает только loopback; честный
разбор — в `docs/PRIVACY.md`, раздел 3.1, порядок добавления своего клиента — в
`docs/OPERATIONS.md`, «Как добавить новый клиент». Опознание клиента не расширяет список
`detok_channels` и не участвует в обезличивании: в модель уходят только коды при любом опознании.

отпечатков. В тестах, документах и скриптах — только заведомые заглушки; правило проверяется
машиной (`tests/test_no_real_pii_in_repo.py`) и включает запрет на значения клиентской базы и на
бренд-слова конкретной сети.

## Проверка кода

```bash
python3 -m unittest discover -s tests        # полный набор: 972 теста (26.09.2026), зелёный
python3 tools/grace_lint_lite.py             # парность разметки модулей, функций и блоков
```

Внутренние контракты модулей (`MODULE_CONTRACT`, `MODULE_MAP`, `START_BLOCK_*`, `START_CONTRACT:`)
— часть кода: на них ссылаются тесты и читатель. Модуль, его идентификатор (`M-…`) и файл
перечислены в `docs/ARCHITECTURE.md`.

Дополнительных зависимостей нет: stdlib Python 3.11, `cryptography`, `pymorphy3`. Сеть в тестах не
используется (loopback-серверы поднимаются на порту 0).
