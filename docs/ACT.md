# Акт теста на обратимую идентификацию обезличенных данных (образец заполнения)

**Оператор:** организация, эксплуатирующая контур (владелец данных и решений).
**Дата проведения:** «дата проведения».
**Основание:** Требования к обезличиванию персональных данных (приказ Роскомнадзора
от 19.06.2025 № 140), регламент обезличивания оператора (раздел 6).
**Объект проверки:** прокси обезличивания `pii-proxy`, режим репетиции
(`PII_PROXY_DRY_RUN=true`), внешний поставщик модели не вызывался.

> Это образец: подставьте свои числа и отпечаток выборки. Готовый акт — доказательство приёмки
> для регулятора, поэтому заполняются все поля, а измерения воспроизводятся командами из раздела 8.

## 1. Выборка

| Параметр | Значение |
|---|---|
| Источник | API системы учёта клиентов (чтение, без изменений) |
| Записей | **100** |
| Дата выгрузки | «дата выгрузки» |
| Отпечаток обезличенного результата (SHA-256) | «отпечаток выборки» |

Отпечаток фиксирует, что именно проверялось, не раскрывая значений: любой может убедиться, что
результат не подменялся, но восстановить данные из него нельзя.

## 2. Методика

Обезличенный результат проверяется тремя независимыми способами восстановления личности:

1. **Прямой поиск значений** — поиск исходных значений и их нормализованных форм (включая
   день-месяц даты рождения) в обезличенном тексте.
2. **Связывание по доступным справочникам** — поиск значений и некриптографических отпечатков в
   файле словаря (телефоны, почта, фамилии, вложенные контакты) и в обезличенном тексте.
   Проверяется и открытая форма словаря, и «наивный» хеш.
3. **Выделение по квазиидентификаторам** — подсчёт сочетаний признаков (клуб, карта, сумма,
   дата), позволяющих изолировать одного человека, и числа групп меньше порога k.

## 3. Результаты

| Способ восстановления | Попыток | Успешных | Комментарий |
|---|---|---|---|
| Прямой поиск значений | «число» | **0** | ни одно значение не сохранилось в открытом виде |
| Связывание по справочникам | «число» | **0** | в файле словаря читаемых данных нет, в запросе значения не найдены |
| Выделение по квазиидентификаторам | «число» | **0** | уникальных сочетаний в выборке не обнаружено |

**Вердикт: личность не восстановлена. Критерий регламента (ноль успешных попыток) выполнен.**

Порог редкости: k = «порог». Групп меньше порога в выборке: **0**.

## 4. Проверка журнала обезличивания

| Параметр | Значение |
|---|---|
| Событий в журнале | «число» |
| Действия | обезличивание, репетиция, предупреждение о редкости, сброс кэша, обновление словаря |
| Классы данных | ФИО, телефоны, адреса, идентификаторы, документы |
| Нарушений закрытой схемы | **нет** |
| Максимальная последовательность цифр в текстовых полях журнала | **0** (значений в журнале нет по построению) |

Обновление словаря и сброс кэша попадают в журнал автоматически: подмена файла словаря
фиксируется событием `dictionary_reload` со сбросом кэша, то есть посторонняя правка справочника
не осталась бы незамеченной.

## 5. Сохранение кэша провайдера (фактор приёмки)

Обезличивание не должно ломать кэш подсказок поставщика модели: разрыв префикса запроса означал бы
рост расходов.

| Проверка | Результат |
|---|---|
| Байтовая идентичность ранее отправленных сообщений между ходами | «число ходов», изменившихся сообщений **0** |
| Повторное обезличивание сохранённого текста (round-trip) | «число строк», расхождений **0** |
| Результат независимой проверки остатков на реальном трафике | остатков не найдено |

Дополнительно в `healthz` выведен счётчик кэша самого поставщика (`provider_cache`: обращения,
токены попадания и промаха, доля попаданий) — после переключения в боевой режим он даёт прямое
измерение, а не расчёт.

## 6. Что тест обязан находить

Тест проводится не для галочки: его смысл — найти классы дефектов, при которых часть персональных
данных уходила бы открытой. Проверяются как минимум:

1. **Нестандартные форматы даты** (`1985-03-12` наряду с `12.03.1985`).
2. **Имена латиницей** — детекторы обязаны видеть их так же, как кириллические.
3. **Контакты с типом в соседнем поле** (`contact_type: phone`): класс определяется соседним полем,
   а не только именем ключа.
4. **Отказ нормализации** на нестандартном формате не должен приводить к тому, что значение уходит
   открытым.
5. **Точность самой проверки** — ложные срабатывания на мусорных данных делают акт шумом, а не
   доказательством.

## 7. Признаваемые ограничения

1. **Владелец контура** (ключи и справочник соответствий) может восстановить значения: защита
   адресована внешнему получателю, а не администратору оператора.
2. **Выделение по редким сочетаниям** обезличиванием не устраняется; для этого служит порог
   редкости (k), включённый в режиме предупреждения.
3. **Обезличенный, но связанный кодами текст остаётся у поставщика модели** — регулируется
   договором и режимом хранения, а не обезличиванием.
4. **Изображения не обезличиваются**: политика — не отправлять изображения с данными клиентов,
   а ответ об этом прямо напоминает (событие `image_notice`).
5. Проверка проводится в режиме репетиции: качество обезличивания измеряется на реальных запросах,
   но боевой обмен с поставщиком при этом не включается.

## 9. Заключение

Обезличивание обеспечивает необратимость в рамках проверенной модели угроз: ни одно из значений
выборки не восстановлено тремя независимыми способами, журнал не содержит значений по построению,
кэш поставщика сохраняется. Остаточные риски перечислены в разделе 7 и приняты осознанно.

## Повторный прогон после смены поверхности идентификатора

После смены формата кода атака выполняется заново, тем же инструментом
(`tools/act_evidence.py`, выборка 100 записей, источник — API):

| Атака | Попыток | Успехов |
|---|---|---|
| Прямой поиск значений | «число» | 0 |
| Связывание по словарю | «число» | 0 |
| Выделение по квазиидентификаторам | «число» | 0 |
| **Итого** | **«число»** | **0** |

**Вердикт: личность не восстановлена.**

Дополнительно к атаке на текст проверяются механизмы, обеспечивающие ограничение восстановления:

1. **Коллизии.** Принудительно занятый код значения отдаётся другому значению — проверяемое
   значение получает следующий детерминированный кандидат; чужая привязка не изменяется.
   Тест: `tests/test_tokenizer.py::test_collision_is_resolved_without_touching_the_other_binding`.
2. **Ограничение восстановления.** Код, которого не было в запросе, значение не подставляет — ни на
   уровне детокенизатора, ни через роутер. Тесты:
   `tests/test_detokenizer.py::test_foreign_code_cannot_inject_another_value`,
   `tests/test_router.py::test_foreign_code_from_the_model_is_not_restored`.

Оценка достаточности метода приведена в регламенте обезличивания одноимённым разделом; расчёт
воспроизводится командой `python3 tools/identifier_sufficiency.py`.
